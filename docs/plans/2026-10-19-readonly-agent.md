# 内部资料问答助手实施计划

**目标：** 交付可以检索内部资料、注明依据并限制工具权限的单用户助手。

**架构：** 复用 FastAPI、LangGraph、现有附件处理及 FAISS 知识库。增加 knowledge 配置档；工具列表与执行节点共用权限定义，不新增业务数据库或框架。

## 方案与取舍

1. 固定检索流程：可控，但需要单独处理多轮问答和附件分支。
2. 受限工具 Agent（采用）：复用已有对话能力，执行层白名单防止越权；事实准确性仍需人工验收。

## 实施步骤

1. 在 `src/config.py` 增加 `AGENT_PROFILE`，保留 general 兼容现有调用。
2. 在 `src/agent/nodes.py` 定义 knowledge 提示和工具权限，在规划与执行阶段共同应用；未知配置启动失败。
3. 在 `src/tools/rag.py` 给检索片段附内容哈希标识，不迁移现有存储。相同内容共享标识，标识不是文件名或版本号。
4. 在 `src/api/main.py` 的运行信息中公开配置档。
5. 增加 `tests/test_knowledge_agent.py`，验证工具可见范围、伪造调用拦截及未知配置拒绝。运行 Python 全量测试与 Ruff/Black。
6. 更新使用文档，启用本地 knowledge 配置并重启托管服务；验证运行信息和健康检查。

## 验收与边界

资料由用户从知识库页面录入，建议正文首行注明标题、日期、适用范围。用真实问题人工确认答案、引用和缺失信息处理；合成测试不代表业务验收。知识库管理、附件上传和对话持久化仍然写入应用数据，工具只读不等于整个 API 只读，也不提供多用户隔离。

## 工程原则

KISS：使用一个配置档和一个白名单。YAGNI：暂不接订单、库存、权限管理和自动发布。DRY：复用注册表、检索模型和执行图。SOLID：配置策略与工具实现分离。

## 后续验收补充

- 在现有 `scripts/evaluate.py` 增加 `--profile`，独立选择合成案例与权限配置；临时数据不进入正式实例。
- 扩大 `tests/test_knowledge_agent.py` 的伪造调用测试到邮件、SQL、HTTP、PDF 和文件写入。
- 实际模型复测暴露两类提示歧义：把对话内复述误认为长期记忆；用无关知识检索结果否定附件已有答案。补充当前对话与附件优先规则，保留失败报告用于比较。
- 验收附件工具统计时，区分服务端预处理记录和模型可调用工具；仅附件案例允许预处理 `pdf_extract` 记录。

## 完整演示资料验收

用户授权运行五份完整演示资料的十二题及改写，共二十四次问答。复用 `scripts/evaluate.py --demo` 的临时实例，仅导入材料正文，不导入标准答案。对比报告保留，不将中途结束的诊断轮次视为完整验收。

新增发现：仅靠提示词，模型仍可能省略可定位片段标识、编造条款号。增加一次有限引用修正和失败拒绝；复用现有消息与上下文预算，不增加依赖。自动筛查覆盖预期要点与精确引用，完整答案另行逐条审阅，尤其注意审批顺序和否定语气。
