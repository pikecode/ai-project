# 内部资料问答助手

在 `.env.local` 中设置 `AGENT_PROFILE=knowledge`，执行 `./start.sh stop` 和 `./start.sh start` 生效。`GET /runtime` 的 `agent_profile` 应为 `knowledge`。恢复通用助手可改为 `general` 后重启。

## 准备资料

从现有知识库页面添加内部流程和制度。每段正文注明标题、生效日期、适用范围；长文按主题拆分。第一批建议录入 3–5 份当前有效资料，先避免混入失效版本。附件仍可直接上传并提问。

## 使用与验收

示例问题：“请根据资料说明报销需要哪些材料，并引用依据。”知识库检索返回 `KB-` 开头的内容标识，附件回答使用页码。标识基于内容生成，不代表来源文件名、审批状态或有效版本。

人工核对至少这些情况：有明确答案、跨段综合、资料未说明、版本冲突、工具失败，以及文档中包含诱导操作指令。记录问题、预期答案、实际引用和耗时，可复用 `docs/PERSONAL_TRIAL.md` 的反馈表。自动化测试验证执行权限，不证明模型事实正确或引用完整。

## 权限边界

knowledge 配置只向模型开放 `knowledge_search`，执行节点也拒绝其他工具，包括伪造的调用。附件提取沿用已有路径。知识库管理 API、上传和对话保存仍可写入应用数据；这是模型工具权限限制，不是整个平台的访问控制。当前仍适用于单个可信用户，不适合直接开放给多个租户。

## 可重复的本地验收

```bash
.venv/bin/python scripts/evaluate.py --self-check
.venv/bin/python scripts/evaluate.py --profile knowledge --output var/evaluations/knowledge-agent.json
```

脚本启动独立临时 API、数据库、上传目录和知识库，使用当前本地模型；结束后清理临时目录，报告保存在指定路径。案例包括续聊、材料检索、精确片段引用、资料缺失、文档诱导操作和附件页码，并检查历史保存、上下文配置、伪造 PDF 和超大输入。附带写入未落盘检查；服务端权限边界另由单元测试验证。

`--profile general`（默认）运行原通用工具验收，明确覆盖本地配置，避免被 knowledge 权限限制干扰。所有案例使用合成资料；通过只说明这组任务本次成功，不能作为事实准确率或对所有诱导输入的保证。

## 冲突资料与检索故障

合成验收新增两份未注明生效日期、且审批人不同的制度，要求答案列出两个审批人、引用两份资料，并指出冲突。测试案例可以用 `documents` 字段在该案例开始前录入独立临时知识库，不影响正式资料。

检索异常由执行图测试注入，检查错误以失败工具消息传给模型节点、而不是伪装成成功结果。该测试使用模拟模型，不能证明真实模型在所有故障情况下都会正确拒答。知识库损坏时应先恢复或修复，不应把“没有搜到”当成“制度不存在”。

## 回答引用检查

资料问答配置会检查有成功检索结果的回答：至少包含一个真实返回的 `KB-` 片段标识，不能引用本次检索之外的标识；回答中的“第几条／章”必须能在所引用原文中找到。不合规则让模型修正一次，仍失败则返回明确错误，不保存为成功回答。修正也受上下文预算限制。

这项检查不能证明每句结论都受引用支持，也不能检测所有表达形式的虚构编号。正文制度编号用于阅读，`KB-` 标识用于定位检索片段。修正可能增加一次模型调用和等待时间。

完整五份演示资料的十二题及改写题运行方式见 `examples/internal-assistant/README.md`；不要把验收答案导入知识库。

## Markdown 章节检索与引用规范化

存在三个以上二级标题的 Markdown 文档，会保留文档标题和头部信息，使用已有嵌入模型选取两个最相关章节；返回 `excerpted=true`。没有这类章节结构的资料保持原行为。原文和持久化格式不变，`source_id` 仍由完整正文计算，因此片段不代表全文。

若正文制度编号能唯一对应本次检索来源，程序可补齐 `KB-` 标识；同号多版本不会自动绑定。已绑定有效来源的回答中，资料未提供的条款／页码定位会改为泛指原文，虚构的片段引用链接会去掉，并显示规范化提示。无法规范化的引用仍只允许一次模型修正，失败则明确报错。

规范化只处理引用元数据，不能纠正业务内容。验收仍需检查全部前置条件、否定语气、适用范围和来源支持。复杂 Markdown、没有标题的长文以及两个章节之外的信息召回仍有局限。
