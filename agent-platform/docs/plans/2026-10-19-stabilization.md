# 核心链路稳定化实施计划

目标：保留 Go 与 Python 的服务边界，修复已有聊天、上传、检索流程，保留现有数据。

## 决策与范围

采用局部修复方案，暂不迁移 Go 前端到 FastAPI，也不引入前端框架、多智能体或微服务。遵循 KISS/YAGNI；普通和流式接口共用执行流程以落实 DRY，上传和文件访问集中在 Python 后端以明确职责。

1. 配置、依赖、安全边界：补齐异步数据库及 PDF 依赖，文件仅访问工作目录，代码执行禁用，任意 HTTP 请求须显式授权域名；本地默认回环监听，可配置共享实例认证。
2. `src/api/main.py` 与 `src/agent/`：统一会话、执行、保存和错误处理，异步执行图按节点实时发送 SSE；校验 ID、更新会话时间。
3. `frontend/`：拆分模板、CSS、JavaScript；统一 Go 代理，保留状态码、超时和取消；安全文本渲染并处理 SSE 分块。
4. 上传：后端负责 PDF 校验与保存，聊天请求携带显式附件标识并保留用户问题。
5. `src/tools/rag.py`：复用实例、加锁、原子存储，兼容读取旧索引，不删除旧文件；当前限定单个 API 进程。
6. 数据库：ORM 为权威结构，SQL 参考脚本字段与 ORM 对齐；旧 PostgreSQL 结构仅经备份后显式迁移，启动不自动改写已有列。
7. 回归测试：Python 覆盖会话、流式、文件边界、上传、知识库与只读 SQL；Go 覆盖代理和认证；Node 覆盖分块事件和文本渲染。
8. 更新 README、部署说明、环境示例和容器配置，运行检查并记录未验证的外部服务。

## 验收

使用临时 SQLite 和模拟模型，不接触现有 `agent.db`。`pytest`、`go test ./...`、`node --test`、Ruff 与 Black 检查通过；真实 Ollama、SMTP 与 PostgreSQL 如无可用实例，明确列为未验证。
