# 资料导入与原文查看实施计划

## 目标与方案

支持 Markdown、UTF-8 TXT、文本型 PDF 的预览与确认导入；回答和搜索结果中的 KB 引用可查看保存的原文。推荐服务端解析并签名预览，确认时校验相同内容；浏览器直接解析更简单，但难以统一 PDF 处理和导入边界，因此不采用。

## 实施步骤

1. 在 `src/tools/rag.py` 为新资料保存文件名、标题、版本、页码与片段位置，兼容无元数据的旧存储和旧引用；原子写入，文件重复确认不重复入库。
2. 新建 `src/api/knowledge.py`，复用 PDF 提取，限定文件类型、大小、文本长度和分段数量。预览不写知识库，签名绑定内容及有效期；确认接口只接受未过期且未篡改的预览。
3. 在 `src/api/main.py` 接入预览、确认和按来源标识读取接口；Go 代理添加明确路由及上传限制。
4. 前端保留完整文档换行，新增文件选择、版本标记、预览与确认状态。只用安全 DOM 渲染引用按钮和原文弹窗，兼容历史回答。
5. 验证旧库读取、持久化与失败原子性、非法文件、PDF 页码、预览篡改、过期、重复提交，以及引用找不到和恶意内容的处理。
6. 用独立实例做浏览器操作验证后，备份并重启正式服务；不向正式库加入测试资料。

## 范围与原则

KISS／DRY：复用上传限制、PDF 提取、检索和原子 JSON 存储，不增加依赖。SOLID：解析预览与知识库持久化分离。YAGNI：暂不增加分库、OCR、版本生效判断或多人权限。版本仅为资料标记；引用查看不能证明答案正确。
