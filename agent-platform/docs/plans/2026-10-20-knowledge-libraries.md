# 日常库与测试库隔离实施计划

目标：固定两套知识索引，导入、检索、引用和会话均显式选择所属库，旧数据默认日常库。

方案比较：两个完整应用实例隔离更直观，但增加进程和端口维护；同一应用内固定两库更便于操作，采用后者。不是多用户权限隔离。

1. 复用 RAGTool，为测试库使用 `RAG_DATA_DIR/test/`，不移动日常文件；嵌入模型与锁复用，索引和元数据独立。现有备份递归包含测试库。
2. 用 Conversation.meta 记录库，旧会话缺省日常库；会话列表、读取和续聊校验所属库，无数据库结构迁移。
3. AgentState携带库，由服务端执行节点选工具实例，不向模型开放切库参数。
4. 知识库API增加限定枚举查询参数；签名预览绑定库，确认时拒绝目标不符。
5. 页面增加明显库选择与状态提示。切库创建新对话、清除预览和附件，异步返回校验库与视图版本，引用绑定产生它的库。
6. 测试跨库导入、引用、会话、Agent执行路由和并发返回；独立实例验证，再备份重启正式服务。

KISS：只支持两个固定库；DRY：复用嵌入模型与持久化实现；SOLID：库选择集中定义；YAGNI：不加入租户、任意库创建或权限系统。共享上传目录、模型服务与数据库不作为多租户隔离边界。
