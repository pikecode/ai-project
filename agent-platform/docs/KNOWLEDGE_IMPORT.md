# 资料文件导入与引用查看

## 页面操作

1. 打开“知识库”，选择 Markdown、UTF-8 TXT 或文本型 PDF。
2. 标题和版本可选填；不填时尝试读取正文标题、`版本：` 行，无法识别则使用文件名和“未注明”。版本是资料标记，不判断制度是否有效；不同版本并存，不覆盖旧资料。
3. 点击“生成预览”，检查全部内容、片段数量和 PDF 提示。此时没有写入知识库。
4. 点击“确认导入”。同一文件内容、标题、版本重复确认不会重复增加片段；改变内容或版本会作为新资料保存。
5. 在对话中提问，点击回答里的 `KB-…` 按钮核对原文；知识库检索结果里的引用同样可点。历史回答也支持。找不到旧引用会说明资料不可用，不展示其他资料代替。

手动粘贴入口现将整段文字视为一份资料，保留换行。后端 `/knowledge/add` 的文档数组接口保持兼容。

## 限制与原文口径

- 单文件最多 50 MiB；提取文字最多20万字符，PDF最多200页，最多100个保存片段，超过任一限制须拆分。
- 每个片段正文最多6000字符；PDF按页分段，长页继续拆分。保留原始页码、文件名、版本和片段位置。超过100个有文字的页通常需要拆分。
- 不支持OCR；部分页面提取不到文字时，预览提示这些页面未导入，需核对原件。触及页数或提取上限时直接拒绝，不悄悄截断。
- 知识库保存提取的文字，不保存可下载的PDF原件。弹窗显示对应片段的原始文字，顶部显示来源信息；多片段文件不能把一个片段当作整个文件。
- 为控制模型上下文，新导入长片段的检索结果可能再次选取相关部分；点击引用仍可查看保存的完整片段。
- 引用能打开只说明资料存在，仍需核对它是否支持回答。

## 预览一致性与兼容

服务端签名绑定预览内容，确认时检查签名和有效期。预览30分钟有效，服务重启后旧预览失效，需要重新生成。预览文件在临时目录解析后清理，不写入上传目录或知识库。确认失败保留预览可重试；同内容确认去重也覆盖响应丢失后的再次提交。

新知识库存储增加与正文对应的元数据数组，仍采用原子JSON写入。旧JSON与受限读取的旧pickle资料仍可读取，既有正文和引用标识不改变；旧资料没有文件名、版本时会如实标为未记录，不猜测。

备份沿用 `./start.sh stop`、`./start.sh backup`、`./start.sh start`；元数据与正文一同备份，无需数据库迁移。此功能沿用单个可信用户的知识库权限，不提供多租户隔离。

## API

- `POST /knowledge/preview`：multipart文件及可选 `title`、`version`，返回签名预览；不导入。
- `POST /knowledge/import`：原样提交预览响应，确认导入。
- `GET /knowledge/sources/{source_id}`：读取保存的内容与元数据。`content` 含入库来源头部，`original_content` 为对应文字片段，均以纯文本展示。

浏览器通过 `/api/knowledge/...` 代理访问，复用现有认证。确认预览是产品操作流程，不是新增的多用户访问控制。

## 日常库与测试库

页面顶部选择“日常知识库”或“测试知识库”。演示文件建议先导入测试库，日常库用于实际资料。切换后开启新对话并清除附件、输入和待确认预览；正在回答、上传或导入时需等待任务结束再切换。刷新页面默认回到日常库。

两库分别保存资料索引、导入元数据与会话归属；检索、引用查看和历史列表均限定当前库。会话创建后不能跨库续聊，签名预览也不能改库确认。旧资料与未标记的旧会话默认属于日常库，已有演示资料不会自动搬走或删除。

日常资料仍在 `RAG_DATA_DIR`，测试资料在其 `test/` 子目录；本地版对应 `var/knowledge/` 和 `var/knowledge/test/`。两库共享嵌入模型以节省内存，备份会递归包含两库，无需数据库结构迁移。

知识库接口以及会话列表、历史读取可传 `?knowledge_base=test`，省略时为 `daily`。`POST /chat` 与 `POST /chat/stream` 在 JSON 正文传 `"knowledge_base": "test"`；后续请求必须与会话所属库一致。

这是单用户的资料与会话分库，不是租户权限边界：数据库、模型和上传目录仍共享；通用助手模式的其他工具也不受分库约束。本地版使用 `knowledge` 模式只开放知识检索。暂不提供资料自动迁移、任意建库和OCR。
