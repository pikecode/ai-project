# 日常库与测试库验收

## 实现与取舍

采用同一应用内的两个固定库，相比运行两套服务减少端口和维护成本。沿用现有RAG持久化、会话JSON元数据及备份机制，不增加依赖和数据库结构迁移。固定枚举遵循KISS/YAGNI，共享嵌入模型遵循DRY，工具执行节点统一选择库以保持职责清楚。

## 边界

仅提供可信单用户的资料与会话分库，不隔离共享数据库、上传目录和其他通用工具权限。旧演示资料仍在原日常库，不自动搬移；跨库迁移、任意创建知识库和OCR未实现。测试没有代替真实制度的业务准确性验收。
