# 内部资料助手演示材料包

全部内容均为虚构，不代表真实企业制度，也不能代替真实业务验收。

## 文件组织

- `materials/`：五份可检索资料，覆盖报销、差旅、账号与设备支持，以及两份故意保留冲突的采购说明。
- `acceptance/questions.json`：十二个常见问题、预期要点、来源文件和人工核对事项。验收过程和限制见 [结果记录](acceptance/RESULTS.md)。

## 使用方法

1. 在独立测试实例的知识库中录入 `materials/` 的文件正文。不要导入本说明或 `acceptance/` 中的答案。
2. 保留资料编号、版本、适用范围与有效性说明。文件名排序不代表制度优先级。
3. 逐一提出验收问题，记录实际答案、来源标识和耗时；人工核对每项预期要点。
4. 检查引用是否支持结论，尤其是800元边界、付款计时起点、跨资料综合和采购冲突。
5. 替换成真实资料时，先移除或隔离本演示材料，避免混用虚构金额和联系人。

当前页面的知识库入口连接正式数据，请勿直接批量导入演示材料。本次仅创建文件，没有修改运行中的知识库。

Markdown 便于修改与检查；若后续需要测试 PDF 解析，可另行制作 PDF 副本。保持一份正文来源，避免维护多份不同步版本。

## 自动运行完整验收

在 `agent-platform/` 目录执行：

```bash
.venv/bin/python scripts/evaluate.py --self-check
.venv/bin/python scripts/evaluate.py --demo --output var/evaluations/demo-check.json
```

`--demo` 会将五份完整正文分别录入独立临时知识库，按原问和改写运行十二题，共二十四次问答。仅发送问题给助手，标准答案与筛查规则留在验收程序内。报告记录完整答案、耗时、缺失引用及未满足的检查项。

自动筛查不是最终结论：需逐条核对审批顺序、拒绝语气、适用范围和引用支持程度，不能以关键词出现代替语义检查。当前正式页面保留原知识库，不会因运行该脚本自动获得五份演示资料。

需要定向复测时，可加 `--case T03 T06`，每个指定题目仍会运行原问和改写。仅拒绝执行越权操作时不要求业务资料引用；若给出具体业务流程，仍需核对来源。自动筛查有误判可能，原始回答必须保留，不能用调整检查规则替代实际问题修复。

完整验收与定向复测结果见 [结果记录](acceptance/RESULTS.md)。结果记录与标准答案都不得导入被测知识库。
